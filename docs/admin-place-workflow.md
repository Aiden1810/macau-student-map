# 管理员地点录入与审核改动说明

实施日期：2026-10-16；2026-10-17 追加人民币单位统一和部署准备。消费参考在投稿、管理员录入、列表及公开地点展示中统一为人民币（CNY）。用户确认历史“芬记烧腊”60 原本就是人民币，保留数值，不执行汇率换算或数据库金额改写。

## 已完成的流程

- 用户投稿维持简洁：饭店、理发、酒吧、桌游／剧本杀等地点类型，以及具体类型、消费参考、位置和图片。
- 管理员“新增店铺”进入新的地点编辑器，不再使用旧版主分类输入框。新增、地点编辑、投稿审核共用此编辑器。
- 管理员可在“编辑并审核”中补全名称、地址、类型、消费、英文名、区域、补充搜索关键词及图片，再发布。原始投稿、投稿人和审核记录保留。
- 地点状态显示为“草稿／已上线／已下架”；旧版审核状态显示为“待审核／已上线／已驳回”。下架数据不进入公开列表。
- 管理员可以选图、压缩、预览、上传及移除。每个地点最多 5 张，支持 JPEG、PNG、WebP；审核前的投稿图片使用限时私有预览，发布时复制到公开存储。
- 图片部分失败会保留已保存地点和未完成操作；重试不重复创建地点。关闭编辑器后，可以从地点管理重新进入并重试投稿图片处理。清理私有源失败也可以继续恢复；已移除的公开图片不会在正常顺序重试时重新出现。
- 原有旧版筛选、统计、导入和维护工具折叠保留。新地点统一写入 `places`；带 `legacy_shop_id` 的旧记录继续由旧版工具维护，避免双向覆盖。

## 标签和搜索的实际含义

“具体类型”和“补充标签”使用现有标准标签目录，合计最多 8 个。具体类型决定饭店菜系或其他服务类型；补充标签描述场景和特点，可以参与既有筛选、搜索。

“补充搜索关键词”是独立的自由文本，每个地点最多 8 个、每个最多 40 字。例如添加“牛腩”后，搜索“牛腩”可以匹配该地点，不需要为此新建标准标签。

当前搜索仍是现有文字归一化、关键词匹配及排序流程，不是 AI 语义搜索；不会保证理解“推荐一个便宜又好吃、适合约会的地方”等任意自然语言。标准标签也不应随意加入主观、无法核实的宣传词。

## Windows 本地运行

```powershell
Set-Location 'D:\项目\CityU_Food'
npm run dev
```

打开 `http://localhost:3000/zh-CN/admin`，使用现有管理员账号登录。如果 3000 已占用，以终端实际输出的端口为准。

建议按以下顺序验收：

1. 新增一个草稿地点，切换地点类型，选择具体类型；从地图选择地点后发布。
2. 上传图片，保存后重新打开，确认图片预览和移除功能。
3. 给地点补充一个独有关键词，到首页搜索该关键词。
4. 在待审核投稿中点“编辑并审核”，核对原稿，补全资料后发布；在地点管理继续编辑。
5. 将测试地点下架，确认公开列表不再展示。对真实投稿执行发布会改变线上数据库，请使用自己准备的测试投稿。
