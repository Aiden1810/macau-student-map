# 城觅 AI 选店助手

用户已确认并要求直接实现：对选中的 A/B/C/D 店比较打车与公交时间；依据人数、人均预算、食物偏好和交通需求推荐其中一家。使用 DeepSeek V4.1 Flash，Key 由用户随后配置。本轮不继续修改店铺资料或坐标，不重构现有系统。

## 设计
- 首页提供独立助手入口，助手页从现有公开地点 API 加载真实已发布店铺，最多选择四家，支持搜索和 A/B/C/D 标记。
- 出发地通过现有高德 POI 选择器确认（可显式请求当前位置并按现有高德坐标体系处理），不用模糊校名或地图中心冒充当前位置。
- 复用高德 JS SDK 加载，独立路线服务调用 AMap.Driving 和 AMap.Transfer。按店铺返回成功、缺坐标、无路线、超时、服务失败等状态，部分失败保留其他结果；打车展示驾车行程估计，不含候车/过关时间；公交展示真实方案时间与线路。
- 服务端从 Supabase 的 published places 读取店铺事实，不能使用客户端提交的店名、价格或标签覆盖数据库。浏览器传递的路线快照需要验证店铺、出发地、终点及新鲜度；用于当前用户比较，不写回数据库或当作官方认证数据。
- DeepSeek 把自然语言与有限历史解释为经过 Zod 校验的条件。推荐与事实句子由代码根据真实候选、价格、标签和路线计算，避免模型凭空编造价格、营业、座位、折扣或交通数字。
- 预算不满足时不强行选店；未知价格不视为免费；人数仅计算参考总额，不保证有位。缺起点或缺路线不声称哪家最快。支持后续问题修改人数、预算或偏好。
- 未配置 Key 时明确显示 AI 待接入，但路线比较可独立运行；不伪装规则输出为模型回答。模型异常/限流/超时提供可重试状态，保留路线表。
- 模型默认 ID 为官方确认的 deepseek-flash。服务端变量 DEEPSEEK_API_KEY、DEEPSEEK_MODEL；调用官方 DeepSeek 地址，不把 Key 放入 NEXT_PUBLIC_*。
- 为中文简体、繁体、英文提供界面文案。与现有绿色风格一致，手机可操作，表格可横向滚动，状态可读，按钮/字段具备可访问名称。

## 验证
先以失败测试覆盖路线单位、缺失结果、无坐标、超时、过期/错终点快照、预算无匹配、未知价格、恶意候选 ID、模型输出校验、缺 Key 和模型失败。再实现并运行完整单元测试、lint、TypeScript 检查和生产 build。真实高德可用路线作独立只读探测；无真实 DeepSeek Key 时仅使用模拟接口验证集成，必须明确说明没有完成实 Key 调用。
