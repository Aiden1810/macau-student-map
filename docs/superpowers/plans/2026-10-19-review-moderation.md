# 用户评价与事后审核实现计划

用户已确认：评价立即公开、管理员事后通过或隐藏；隐藏评价不计分；本人可以编辑删除，被隐藏内容不能通过修改或删除后重发绕过审核。

沿用 reviews、现有评价页面和后台导航，不重构地点资料。用独立审核状态区分“待审但公开”与“待复核且隐藏”。删除采用前台移除、后台保留记录，保护审核决定。所有写入走校验身份的数据库函数，锁定地点后更新评价和评分，保留原有人工资料。

1. [x] 数据库：新增审核字段、软删除字段、本人写入和管理员审核函数；修正普通用户评分汇总权限；加入版本冲突与发布频率限制。
2. [x] API：公开列表/评分、本人评价读取和写入、后台分页审核；验证输入、权限、精确版本和未知请求结果。
3. [x] 用户端：原评价回填、修改、确认删除、审核说明、登录返回、提交后刷新。
4. [x] 后台：新增用户评价入口，筛选待审/通过/隐藏，展示店铺、作者编号、内容、分数和审核原因，逐条处理。
5. [x] 验证：先写失败测试，再实现；在独立内存 PostgreSQL 中验证权限、隐藏、复核、软删除后重发、评分汇总和审计。运行测试、lint、TypeScript、i18n 和 build。

重点覆盖：普通用户不能修改他人或审核字段；待审评价公开但被驳回后编辑仍隐藏；删除后恢复不能越过审核；审核旧版本必须冲突；隐藏/删除最后一条后均分为空。数据库迁移仅准备并在隔离环境测试，不擅自应用到正式数据库或发布网站。

新增测试依赖：@electric-sql/pglite（隔离的 PostgreSQL）、jsdom（模拟浏览器测试用户操作）；均为 devDependency，不进入产品功能。
