# 管理员地点录入与审核 Implementation Plan

> **For agentic workers:** 使用 executing-plans 在当前会话连续实施；用户已明确批准上述方案并要求直接开始。

**Goal:** 用户简洁投稿，管理员通过共用编辑器新增、完善、发布和维护新 places 地点，支持真实图片上传与中文状态。

**Architecture:** 保留现有页面和旧数据兼容功能；新管理入口统一到 places。受管理员授权的 API 调用原子数据库函数保存地点及标签、审核投稿，保留原始投稿并记录审计。图片复用现有压缩组件、Storage 和审核迁移逻辑。

**Tech Stack:** 现有 Next.js、React、Zod、Supabase、Vitest，无新增产品依赖。

**Spec:** 本聊天中已确认的六项修改建议，以及用户“现在直接开始做”的执行授权。

## Global Constraints

- 保留现有用户投稿简洁界面，不增加关闭按钮。
- 新增和审核共用地点类型、标准标签、消费与坐标规则。
- 状态中文显示，数据库状态值保持兼容。
- 管理员补充搜索关键词能被首页搜索匹配；不将当前关键词搜索冒充自然语言理解。
- 不改动真实评分统计；保留原始投稿人、资料及审核审计。
- 非管理员不能新增、修改、审核或上传管理图片；私有投稿图片使用限时签名预览。
- 不删现有数据、不推送或自动部署；必要数据库迁移可应用并验证。

## Review Focus

- 错误分类/标签及缺失或越界坐标必须被前后端共同拒绝。
- 重复点击或网络重试不能重复发布同一投稿。
- 图片失败不能显示全部成功或重建重复地点；保留可重试状态。
- 保存普通资料不能清空用户评分；下架状态不进入公开列表。
- 投稿修改冲突和已被审核的稿件必须明确处理；原稿不可被管理员覆盖丢失。
