# 用户评价与事后审核

本轮在现有结构上补齐评价流程，没有部署网站，也没有执行远端迁移或写入真实评价、店铺资料。原有 56544 预览继续保留。

## 已实现的规则

- 登录后每个账号对每个地点保留一条评价；必选 1～5 整数星，文字可选、最多 3000 字。
- 首次发布立即展示并计分，管理员在后台事后审核。
- 后台新增“用户评价”，支持待审核、已通过、未通过、用户已删除及全部筛选，每页 20 条。
- 隐藏需填写至少 3 字的原因，作者能看到原因。隐藏评价不公开，也不计入店铺均分和评分人数。
- 被隐藏的评价修改后仍不公开，等待管理员重新通过；删除后重发也不能绕过审核。
- 用户可以查看、修改自己的评价，删除前需确认。删除采用软删除：前台移除，后台保留记录；管理员不能恢复用户已删除的评价。
- 发布、修改、删除、审核和评分聚合在数据库事务中完成；操作使用精确更新时间避免覆盖他人刚修改的版本。
- 新增和修改评价间隔至少 10 秒；重试相同内容不会重复创建评价或增加人数。
- 未登录时先引导登录，并携带安全的站内返回路径；会话 token 自动刷新不清空草稿。
- 详情页提交后刷新评价和评分。少于 5 人评分时提示仅供参考，未评分显示“暂无评分”；原有推荐门槛保留。

## 启用与验收

本轮只是本地开发和验证，不能认为功能已经在线启用。新迁移需要和新应用版本配套；本次没有重复运行 `20261019081749`。

后续获得发布授权后，先部署兼容升级提示的新应用，再安装本次新迁移并做真实账号验收。迁移前新评价 API 会提示功能升级。迁移会禁止旧 API 的直接评价表写入，因此不能安装迁移后长期继续运行旧版评价 API；回退代码时也要一起检查数据库兼容性。安装过程不回填评分、不修改店名、地址、价格、标签、图片或发布状态。

验收顺序：普通账号首次评价即时公开 → 编辑后评分人数不增加 → 取消删除无变化 → 确认删除后分数移除 → 管理员隐藏时填写原因 → 作者修改仍隐藏 → 管理员重新通过后恢复分数。正式测试只选专用测试地点和账号，避免更改真实店铺资料。

邮箱登录回跳仍需 Supabase 的 Redirect URLs 允许当前站点的回调地址；本轮未更改该线上配置，也未发送登录邮件。后续可按实际使用情况再增加举报、图片和回复。
