# 城觅 2.0 P0 审查笔记

审查日期：2026-11-23。范围为原版仓库当前源码、迁移及发布记录。下文的「源码已确认」描述静态实现，「推断风险」描述该实现的可能影响，「需要实际测试」列出待验证项。本轮未连接生产数据库、读取凭据或调用付费 API。

## 当前架构与产品方向

- 原版采用 Next.js App Router、React、TypeScript、next-intl、Supabase Auth/Postgres/Storage 和高德 JS SDK。首页经 `/api/places` 加载已发布的内部目录，详情及收藏使用内部地点 ID。现有 DeepSeek 助手和后台地点、投稿、评价管理继续沿用。依据：[首页](../../app/%5Blocale%5D/page.tsx)、[公开目录](../../app/api/places/route.ts)、[助手](../../app/api/assistant/chat/route.ts)。
- 已确认的方向是高德按需提供附近及城市、区域、类别搜索，拒绝定位时可手动搜索。地图覆盖餐饮与生活服务，城觅管理原创推荐及独立地点资料。保留未收录地点的手工投稿渠道、旧详情和用户数据。
- 继续使用 `places.id` 作为内部主键。第三方 POI 标识通过受许可的映射关联，浏览本身不创建地点记录。普通推荐与核验学生推荐分开标识。明确硬条件先筛选，学生评价信号只做有限加权。比赛版用于参考查询和选餐逻辑。

## 发现与优先级

### 高｜待审评价可公开读取和计分

- **源码已确认**：新评价写入 `status='published', moderation_status='pending'`。已发布评价被编辑时保留公开状态并回到待审。公开 RLS 对 `anon`、`authenticated` 只要求评价已发布、未软删除、所属地点已发布，未要求审核通过。评价媒体行的公开策略同样未判断审核状态。匿名 GET 使用公开 Supabase 客户端，返回正文、评分和公开汇总，同样只筛公开和未删除。评分刷新查询也只筛公开和未删除。依据：[评价迁移第 27–56、94–101、146–147 行](../../supabase/migrations/20261019110033_review_post_moderation.sql#L27)、[API 入口第 3 行](../../app/api/places/%5Bid%5D/reviews/route.ts#L3)、[GET 第 204–230 行](../../lib/reviews/handlers.ts#L204)。
- **推断风险**：包含个人信息或违规内容的待审正文、编辑稿和评分可能在审核前公开。媒体行可读并不能单独证明对象文件可下载，文件仍取决于 Storage 桶和对象权限。仓库文档明确把现有流程定义为事后审核，因此这是已确认的行为及内容治理风险。拟新增的学生推荐须使用先审后发。依据：[评价设计](../review-moderation-2026-10-19.md#L8)、[历史发布记录](../release-2026-10-20.md#L14)。
- **需要实际测试**：在隔离环境用匿名、其他用户、作者和管理员验证新建、编辑、驳回、隐藏、软删除、媒体和评分变化，同时覆盖 GET 和数据库公开读取路径。当前线上部署、实际 RLS 和内容暴露范围留待授权后核验。

### 高｜高德 JS 安全码存在客户端公开路径

- **源码已确认**：浏览器读取 `NEXT_PUBLIC_AMAP_WEB_KEY`，加载器把 JS Key 放入 SDK 请求 URL。配置了 `NEXT_PUBLIC_AMAP_SECURITY_CODE` 时，浏览器把安全码写到 `window._AMapSecurityConfig.securityJsCode`。涉及主地图和共用加载器。浏览器型 JS Key 设计上可见，风险主要来自客户端明文安全码及绑定限制不足。依据：[主地图第 327–337 行](../../components/MapPlaceholder.tsx#L327)、[加载器第 168–174、202 行](../../lib/amap/place-search.ts#L168)。
- **推断风险**：若生产构建配置了该安全码，访问浏览器即可取得它，可能导致配额被滥用。实际使用的鉴权模式、白名单及是否发生滥用尚无证据。
- **需要实际测试**：在测试环境验证 `serviceHost` 同源代理、密钥仅服务端可见和域名限制。由维护人员在高德控制台确认原版独立 Key、权限、配额和凭据轮换安排。依据：[高德安全密钥说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

### 中｜地点合并或删除可能破坏旧数据关系

| --- | --- |

| `reviews` | `place_id` 和 `user_id` 分别指向 `places` 和 `auth.users`，删除级联。同一用户与地点组合唯一。 [基础迁移第 167–179 行](../../supabase/migrations/20260830103144_canonical_local_life_model.sql#L167) |
| `place_submissions` | `source_place_id`、`merged_into_place_id`、`published_place_id` 分别记录来源、合并与发布地点，均指向 `places.id`，删除地点时置空。投稿人、审核人另与账号关联。 [基础迁移第 111–129 行](../../supabase/migrations/20260830103144_canonical_local_life_model.sql#L111)、[编辑器迁移第 4 行](../../supabase/migrations/20261016152029_admin_place_editor.sql#L4) |

**推断风险**：直接删除或重建地点会丢失收藏、评价或投稿追溯关系。直接并表可能撞上一人一店约束。**需要实际测试**：测试环境用合成数据检查同名分店、重复收藏和评价的冲突处理，核对三条投稿关系及旧链接。新增外部映射，保留旧 UUID，优先用归档或经审计的别名处理合并。

## P1 动态地图前置条件与下一步

1. **高德官方待确认**：应用对外展示方式、归属标识、授权和配额。另行确认 POI ID 与旧 ID 映射能否持久化、允许的字段及缓存期限。持久关联许可直接影响 P2，合规的即时查询原型可独立推进。依据：[高德开放平台服务协议第 4.12 节](https://lbs.amap.com/pages/terms)。
2. **P1 的测试环境条件**：同源代理及 Key 限制可验证，明确澳门、珠海的搜索范围，实测拒绝定位、跨区、分店、类别覆盖和空结果。明确超时降级、调用频率及额度保护，保留原目录入口、旧详情和收藏回归基线。
3. **当前评价风险单独处理**：原版事后审核是否继续需产品明确。若改为先审后发，统一修正提交和编辑流程、公开 RLS、GET、媒体和评分聚合，先在隔离环境验证。地图独立原型可准备，P1 扩大公开曝光前应有明确处置决定。
4. **后续授权事项**：生产环境只读确认当前部署、迁移、RLS、桶权限和高德配置状态。P2 前确定学生核验、撤销和审核责任。没有授权或阶段批准时保持当前状态。


## 修复分支与上线前核对

修复位于 `codex/chengmi-p0-security`。以下是分支行为，前述发现保留为修复前基线。

- **评价**：新增 [先审后发迁移](../../supabase/migrations/20261123103000_require_review_approval.sql)。新评价和有实际修改的评价进入待审，保留同一评价 ID。复审期间整条评价及其评分暂时下线。公开 API、RLS、媒体元数据及评分触发器都要求已批准、已发布、未删除。作者和管理员继续按原权限查看及操作。公开评价响应继续使用 `no-store`，写入和审核沿用公开地点缓存失效。数据库迁移自身不会触发 Next.js 缓存失效，发布时应刷新 `public-places` 或等现有 30 秒重验证窗口结束后核对。
- **历史数据**：迁移事务只将已发布但待审的历史记录改为待审，并触发受影响地点评分重算。保留评价、作者、地点、收藏、投稿及审核审计关系。已批准评价保留。先在授权的隔离环境估算迁移影响、备份并验证。若投稿桶未配置为私有，或有评价媒体指向公开桶，迁移会回滚并报错。需先由管理员用 Storage API 保全文件、迁至私有存储并更新关联，停用旧公开副本及处理 CDN 缓存或仍有效的签名链接，再重跑。当前评价界面没有评价图片发布入口，本次保护现有媒体记录与存储边界。
- **回滚**：优先回退应用版本并保留先审后发迁移。异常时暂停评价写入及公开读取，再用经过审批的前向补丁修复。恢复旧 RLS 或旧保存 RPC 会恢复先公开后审核的行为。不要用旧备份覆盖上线后的新增评价，也不要把待审状态批量改回公开。迁移事务报错会整体回滚。
- **高德**：统一使用 SDK 的同源 `/_AMapService`。代理仅接受当前功能的固定高德 HTTPS 路径、有限参数和本站 JS Key，设置请求超时、单实例限额和禁缓存，并过滤错误及响应中的安全码。定位、搜索和路线插件仍沿用原有调用方式。真实 SDK 插件请求形态仍需授权环境验证。单实例限额需要配合部署平台的路径级限频和高德配额告警，才能覆盖多实例流量。
- **人工配置**：高德控制台确认当前 JS Key 的授权域名及配额。若旧构建曾包含公开安全码，安排在控制台轮换，然后把新码写入部署平台服务端变量 `AMAP_JS_SECURITY_CODE`，移除旧公开变量并重建。保留公开 JS Key，除非控制台要求成对重发。清理可访问的旧构建及缓存。使用非生产凭据验收地图、定位、POI 搜索和路线，再安排发布窗口。 [高德安全代理说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)

隔离验证通过全量测试 697 项、收尾改动后的定向测试 109 项、ESLint、TypeScript、三语文案检查和 Next.js 构建。构建的客户端产物未检出两种模拟安全码或对应变量名。回环 HTTP 验证确认代理路由能拒绝错误 Key，成功转发与限额使用 Mock 验证。真实高德插件和生产 Storage/CDN 仍待授权验收。

本轮未部署、未运行生产迁移或变更高德控制台。

## 审查 follow-up 与发布阻塞项

- **代理边界**。公开 JS Key 只能用于匹配本应用的凭据。Origin、Referer 和 Fetch Metadata 能限制浏览器跨站请求，非浏览器客户端仍能伪造。每实例每分钟 120 次、最多 8 个并发上游请求。冷启动、多实例、多个区域及分钟边界都可能放大总量。这些限制不能替代入口限流或供应商额度上限。
- **协议与人工验收**。固定高德上游和完整路径允许列表。原版使用 PlaceSearch、Geolocation、Driving、Walking 与 Transfer，地图控件和标注继续由 SDK 加载。官方文档说明了代理和插件接入，未承诺这些插件内部的实际路径、参数及回调命名长期稳定。用授权测试凭据逐项验收底图、搜索澳门和珠海、定位授权与降级、驾车、步行、公交。只记录请求路径、参数名、状态、耗时及体积，不保存凭据、查询内容或经纬度。核实同源浏览器请求头、JSONP 回调、分页取值、8 秒超时与 2 MiB 解码体积上限。若有合法请求被拦，凭记录逐项增补。 [高德安全代理](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)、[高德插件](https://lbs.amap.com/api/javascript-api-v2/guide/abc/plugins)、[高德路线规划](https://lbs.amap.com/api/javascript-api-v2/guide/services/navigation)
- **Vercel 入口限流**。获批后在项目 Firewall → Configure 新建 Custom Rule。Path 以 `/_AMapService/` 开头，采用固定 60 秒窗口、Vercel 观测的 IP 作为计数键。可从每 IP 每分钟 30 次开始，在测试项目覆盖共享校园网络与多个实例，再调整并审核发布。超限应在函数执行前拒绝。在 Firewall 流量视图按规则检查 429、误伤率及突增。发布前核对套餐包含量和超额价格。现有额度无法承担时，需批准费用或采用已有的等效入口防护。配置跨实例限流前阻塞公开发布。 [Vercel WAF 限流](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting)
- **总量、账单和响应人**。每 IP 限流无法控制分布式总量。高德控制台核对独立生产 JS Key、允许域名、日/月流量、QPS、超额扣费方式和余额。可用时设定经批准的供应商硬上限，启用流量、QPS、调用失败和安全告警，明确短信或邮件接收人。若没有可接受的总量硬上限，需先批准等效共享总量门槛或维持关闭。按现有套餐启用 Vercel 支出通知，核实暂停能力和影响范围。Vercel 支出控制不覆盖高德账单。流量告警触发时由值班人先在 Firewall 暂时拒绝代理路径，再排查。确认曾暴露安全码时人工轮换并同步更新服务端变量。 [高德风险报警](https://lbs.amap.com/api/cooperation/jkd)、[Vercel Spend Management](https://vercel.com/docs/spend-management)
- **数据库锁与回滚**。迁移设置 3 秒锁等待上限和每条语句 60 秒执行上限。先锁地点表，再调整评价策略和触发器。回填在同一事务暂时停用单行评分触发器，每个受影响地点只重算一次，随后恢复。仍需持有评价及媒体表的 DDL 锁，并写入历史行。大表须先用有代表性的合成数据在隔离环境测量，再批准低流量维护窗口。超时后检查事务回滚和阻塞来源，再决定是否分阶段执行。测试注入回填失败，确认旧 RLS、记录、评分和触发器恢复。
- **Storage 边界复核**。仓库中私有投稿桶的对象读取只开放给对象所有者和管理员，公开地点桶可绕过读取 RLS。评价媒体的公开策略已要求审核通过，仓库里的媒体 API 查询的是 `place_media`，未找到独立的评价附件公开入口。仍需在授权环境核对实际策略、已签发 URL、历史公开副本和 CDN。未核实前不发布数据库迁移。 [Supabase Storage 桶权限](https://supabase.com/docs/guides/storage/buckets/fundamentals)

本轮隔离定向测试 16 个文件、132 项通过。Lint、TypeScript、Next.js 构建通过，客户端产物未检出两种模拟安全码。未运行真实高德请求或生产迁移。

## 2026-11-25 高德复测

- 实际来源 `127.0.0.1:56544` 的珠海关键词查询、坐标转换、逆地理编码和单条步行规划得到 `10000`。定位通过浏览器模拟设备读数，路线与地址由高德返回。
- 选餐页使用真实 SDK 时，本地代理拒绝了 Walking 插件发送的 `multipath=0`，返回 HTTP 400。代理现在仅在步行路径接受此单路线选项。回归覆盖原请求、其它路径、重复参数和其它取值。SDK 的 `/v3/log/init` 仍返回 404，已成功的搜索、定位和步行调用无需放行该路径。
- 澳门城市大学出发场景修复后有三条有效路线，一次请求得到 `10021`，即账号的接口 QPS 达到上限。测试保留部分结果，页面区分超时或查询失败、未取得路线和超过步行时限。发布前仍需按开通配额确认请求频率、跨实例限流及报警。 [高德错误码](https://lbs.amap.com/api/webservice/guide/tools/info)
- 测试版使用完整本地迁移链补验评价先审后发和用餐记录隔离。真实 Supabase Auth、PostgREST、Storage 及生产发布前检查仍待授权测试环境。 [测试版验收](product-roadmap.md#2026-11-25-测试版验收)
